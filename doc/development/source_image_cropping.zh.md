# 通用图片裁切：阅读器与漫画源契约

阅读器不包含站点名、域名或广告识别规则。源负责开关、识别与过滤；阅读器负责
图片操作、范围校验、缓存、预览及手动覆盖。旧源的 modifyImage 行为保持不变。

## 源直接提供裁切范围

comic.onImageLoad 可以返回新的可选字段 cropBands：

```javascript
onImageLoad: (imageKey, comicId, epId) => ({
    url: imageKey,
    // 仅为接口示例，实际范围由源决定；关闭时返回 [] 或省略字段。
    cropBands: [{top: 0, bottom: 0.08}, {top: 0.92, bottom: 1}]
})
```

每项移除一个全宽横带，坐标为 0～1，相对于同一张输入图片，不是逐次裁切后的坐标。
允许顶部、底部和中间区域；最多 32 项。重叠区域合并后总高度不得超过 30%，
每项至少 0.5%。NaN、越界、反向和过量范围会作为无效配置拒绝。
执行顺序为 onResponse → 保存原始缓存 → modifyImage → cropBands → 保存处理缓存。
如果同时提供 modifyImage，cropBands 的坐标相对于 modifyImage 的结果。
不支持的图片格式、动画或超过 1200 万像素的输入不会被横带裁切。

## 源需要检测像素时

现有 modifyImage 脚本中的 Image 新增两个方法：

- image.getPixel(x, y)：整数像素坐标，返回 {r, g, b, a}，每项 0～255。
- image.removeHorizontalBands([{top, bottom}, ...])：返回新的 Image，输入不变，
  使用相同的校验、重叠合并和原图坐标语义。不要对同一范围重复使用 cropBands。

```javascript
function modifyImage(image) {
    // 源在这里进行自己的识别；无法确认时直接 return image。
    return image.removeHorizontalBands([{top: 0, bottom: 0.08}]);
}
```

脚本在独立引擎运行，不能捕获源实例。在返回脚本前将源设置序列化进去。
独立广告图片仍由源在 loadEp 返回图片列表前过滤，阅读器不猜测广告内容。
源设置继续使用既有 settings / this.loadSetting，不增加阅读器专用站点设置。
旧阅读器不支持 cropBands 和新增 Image 方法，源发布时应注明所需阅读器版本。

## 手动工具

底部“移除图片横向区域”适用于所有源及本地图片。可以添加多个横带，预览拼接结果、
清空选区、删除末个区域，或选择：

- 恢复原图：保存空列表，跳过该页的源处理与全局图片处理。
- 使用源处理：移除本页手动覆盖，重新使用源处理缓存。
- 应用：保存当前手动区域并在原图上处理，优先于源处理。

原有 readerImageBannerCrops 设置键保持不变，旧 {top,bottom} 自动读取为单区域。
新格式为 {bands:[{top,bottom},...]}。无记录表示使用源；空 bands 表示原图。
保存设置时更新图片版本，避免重新进入阅读器后命中旧的已解码图片。
手动预览显示原始图片与当前手动裁切结果，不自动执行源检测。

## 缓存与下载

原始图片是 onResponse 解密/转换后的字节，键为原图片缓存键加 @original。
源处理结果保持原缓存键，在线显示和离线下载沿用同一下载处理链路。
原图恢复和手动调整不覆盖两个磁盘缓存。重新加载图片会清除二者，重新请求源。
原始缓存也受普通缓存容量和清理规则约束，不能保证永久存在。
旧缓存或被清理的原图会提示重新加载，不把已经裁过的图片当成原图。

源设置/规则变化后，已有的源处理缓存不会自动重新生成，需重新加载图片。
已下载的文件保存当时的源处理结果；离线恢复只能恢复本地文件本身，不能找回
下载时已经移除的内容。要改变已下载的源处理结果需重新下载。

此阶段只实现通用能力；不包含包子或其他站点的识别脚本。
