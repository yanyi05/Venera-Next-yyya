# 自动补传与多设备记录合并

本版本默认使用记录同步，保留基本 WebDAV 的 PROPFIND、GET、PUT 兼容性。
已有同步模式不自动改变；要持续自动同步，在应用 → 数据同步中选择“实时”。
所有设备须升级到这个版本。旧版只认识 `.venera` 整包，不能读取新记录文件；
新协议建立后不持续接收旧客户端继续写入的整包。原备份文件保持原样。

## 行为

- 阅读优先修订：阅读器持有阅读保护，打开期间暂停同步及远端导入，本地进度仍正常保存。
- 退出阅读器并完成最后一次进度保存后，通常约 2 秒开始补传；旧任务尚在收尾时需等待它完成。
- 阅读器以外的实时改动约 10 秒后合批同步。数据库扫描、记录合并、哈希、JSON 和同步日志写入由后台 Isolate 执行。
- 前台空闲每 60 秒检查远端；启动、恢复前台时检查；进入后台尝试同步。
- 失败按 10、20、40…秒退避，最多 300 秒；手动模式只保存改动，不自动联网。
- 每次同步都先捕获本地已保存的数据，再合并远端，再上传本地改动。
- 上传期间发生的新改动保留待同步状态，不被上一批上传的完成回调清掉。
- 系统杀掉应用后无法继续联网；下次启动先扫描本地数据库，恢复未发送的改动。

## 合并范围及规则

历史和收藏按数据库记录合并；历史的章节访问集合拆成独立记录，因此可合并两端
分别访问的章节。阅读位置以最近修改的记录为准，允许从后面重读到前面，不能简单取最大章。
这里的“已访问”沿用应用原有含义，不表示已经看完整章。

设置按字段合并，源脚本/配置按文件合并，图片收藏按漫画记录合并。
本机连接配置、设备身份、自定义排除字段保持本机值；漫画归档连接配置遵循原有
`backupWebdavSyncEnabled` 选项。Cookie、下载图片、图片缓存和本地漫画文件不走此记录协议。
同一个设置字段中的复杂对象、同一漫画的图片收藏、同一个源配置文件仍以整项为单位解决冲突。

修订携带设备计数与因果上下文。观察过旧修订后的新修改优先，不依赖设备时间正确；
两台离线设备并发修改同一项时，用时间和设备标识确定一致结果。
并发删除优先；看见删除后主动重新添加可以生效。已知章节的重置携带删除标记，
旧记录重新上线不会单靠旧快照复活已删除的项。
累计阅读时长的并发冲突取较大值，不把两台设备的累计值相加；同时离线阅读可能少记时长。

## 持久性与恢复

`record_sync.db` 保存独立设备身份、端点/排除策略的状态、待发送记录、正在上传的确切
内容及未完成的导入计划。它不进入普通数据导出，不能把这个文件复制到另一设备作为同步方式。
SQLite 使用完整同步写入。上传批次按内容 SHA-256 命名，可在断线或丢失响应后重传。
未完成的 PUT 先修复，再读取远端列表，避免自己留下的残缺文件堵住后续合并。

合并提交前记录前后投影，实际导入沿用现有的归档替换和回滚机制。
中断后只重放仍匹配修改前值的项，保留中断后产生的独立本地修改。
网络等待不占用全局数据锁；下载结束后重新捕获本地状态，避免覆盖等待期间的翻页。

第一次连接仍只有旧备份的目录时，读取版本号最大的旧 `.venera`，按记录加入，
不从“旧备份缺少某项”推断删除；发布包含迁移结果的完整记录检查点。

## 云端整理

普通批次只发送变化项。达到 64 个记录文件时，发布包含所有有效修订及删除标记的
检查点，重新下载核对内容，然后才尝试删除这个检查点确实覆盖的旧记录文件。
其他设备同时新建的文件、旧 `.venera` 备份不在删除列表中。
整理也保留本机排除字段的远端修订，避免影响其他设备需要同步的字段。
服务端不支持 DELETE 时继续同步，旧批次会留在云端。
检查点持续保留删除标记，不能为节省空间直接丢弃它们，否则长期离线设备可能复活旧项。

## 验证及限制

新增测试覆盖双设备离线修改、重读位置、章节合并/重置、收藏删除、进程重建后的补传、
中断 PUT 修复、等待网络期间继续修改、损坏批次、提交失败恢复、旧备份迁移、
检查点整理与排除字段保留，以及自动合批、退避、轮询与手动模式。

真实应用导入使用原有 ZIP 原生库；这里没有改变它。当前 Windows 验证环境缺少
`zip_flutter.dll`，且无法创建部分目录别名，因此不能宣称全量同步测试或真机验证通过。
部署后还需在两台测试设备、实际 WebDAV 服务上检查阅读、断网及重启行为。
